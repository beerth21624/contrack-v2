# 00 — วิสัยทัศน์ การตัดสินใจของเจ้าของ และขอบเขต

สถานะ: ข้อกำหนด (requirement) จากการระดมความคิดกับเจ้าของ · 2026-10-31

## 1. เป้าหมาย

ยกระดับ ConTrack จากแอปประมาณราคา BOQ สำหรับผู้รับเหมาไทย ให้เป็น **ERP งานก่อสร้างสำหรับผู้รับเหมาขนาดเล็กถึงกลาง**
ตัวประมาณราคา BOQ เดิมจะเป็น **โมดูลหนึ่ง** ของระบบ และ **รายการ BOQ คือกระดูกสันหลัง**: ทุกบรรทัดของ BOQ ใน baseline
ทำหน้าที่เป็น **cost code** ที่งบประมาณ PO จ้างช่วง ค่าแรง % ความคืบหน้า และการวางบิลอ้างถึง

## 3. ขอบเขต

### 3.1 ทำตอนนี้ (ทั้งหมดอยู่หลัง flag)

Foundations (ข้ามโมดูล):
Project Hub, ประวัติ BOQ และ baseline, cost codes และ cost ledger, บริการเลขเอกสาร, i18n TH/EN, business profile และ project type,
entitlement และ dependency ของโมดูล, บทบาทและสิทธิ์, workflow อนุมัติ (ข้ามเองเมื่อทำคนเดียว), การแจ้งเตือนในแอปที่พร้อมต่อ LINE,
ทะเบียนลูกค้าแบบเบา, โปรไฟล์บริษัท (ข้อมูลภาษีและโลโก้), ลิงก์สาธารณะสำหรับลูกค้า (รับ/ขอแก้ใบเสนอราคาและ VO), audit log,
ข้อมูลราคากลางภาครัฐ (นำเข้า `goverment_price.json` เป็นแหล่งอ้างอิงราคา)

โมดูล ตามลำดับความสำคัญ:

| ลำดับ | โมดูล | ModuleId |
|---|---|---|
| 1 | ใบเสนอราคา | `quotations` |
| 2 | สัญญาหลัก + งวดงาน (`contracts`) และการวางบิลตามผลงาน + ลูกหนี้ (`billing`) | `contracts`, `billing` |
| 3 | งานเพิ่ม-ลด (VO) | `variations` |
| 4 | Portal / หน้าหลัก (บน Project Hub) | `portal` (และ `project-hub`) |
| 5 | จัดซื้อ (PR → RFQ → PO → รับของ) + ทะเบียนผู้ขาย | `procurement` |
| 6 | รายงานประจำวัน (`site-diary`) + ใบลงเวลาค่าแรงและงวดจ่าย 15 วัน (`labour`) | `site-diary`, `labour` |
| 7 | ควบคุมต้นทุนโครงการ + กระแสเงินสดจริง | `job-cost` |
| 8 | เจ้าหนี้ + 50 ทวิ + รายงานภาษี + export ให้นักบัญชี | `payables` |
| 9 | ส่งมอบงาน รับประกัน และปิดโครงการ | `handover` |

ประวัติ BOQ, baseline และ cost code อยู่ใต้ ModuleId `boq-control`

### 3.2 ไม่ทำตอนนี้ (LATER)
บัญชีแยกประเภท (GL), เงินเดือนและ HR, marketplace แบบเปิด, owner portal, CRM เต็มรูป, QC/punch list, คลังวัสดุหน้างาน,
เครื่องจักร, ความปลอดภัย, offline/native app, PDF ฝั่ง server (ใช้พิมพ์จากเบราว์เซอร์เหมือนเดิม), การส่ง LINE จริง (ทำแค่ abstraction),
การชำระเงินออนไลน์ (สร้าง PromptPay QR ได้ แต่ไม่ยืนยันการโอนอัตโนมัติ), e-Tax invoice ส่งกรมสรรพากร

### 3.3 สิ่งที่ระบบ "ไม่ทำ" ตามหลักเดิม
ระบบ **บันทึก** เงิน ไม่ถือเงินแทนใคร (เหมือนหลักข้อ 11 ของโมดูลจ้างช่วง) การออกใบกำกับภาษีเป็นการออกเอกสารของบริษัทผู้ใช้เอง
ผู้ใช้รับผิดชอบความถูกต้องทางภาษี ส่วนระบบรับประกันว่าเลขเอกสารไม่ซ้ำ ไม่ข้าม และเปลี่ยนไม่ได้

## 4. โปรไฟล์กลุ่มลูกค้า (ค่าเริ่มต้นตาม project type)

ค่าเหล่านี้อยู่ในโค้ดที่ `src/domain/erp/profiles.ts` (สร้างใน WP-12) workspace แก้ทับได้ใน `company_profiles.defaults`
และแต่ละโครงการเก็บสำเนาไว้ใน `projects.settings` ตอนตั้ง project type

|---|---|---|---|---|

## 6. นโยบายการปล่อยด้วย feature flag

ธง 4 ชั้น ต้องผ่านครบทุกชั้นโมดูลจึงจะ "active" (รายละเอียดใน `01-architecture.md` §4):

1. **Release flag** (server env `MODULES_ENABLED`, มีอยู่แล้ว): เซิร์ฟเวอร์นี้เปิดให้โมดูลนี้หรือไม่
2. **Entitlement** ต่อ workspace ที่ platform admin กำหนด: `purchased` / `trial` (30 วัน) / `beta`
   โมดูลเดิม (`subcontracting`, `workforce`, `ai-assist`) ไม่ต้องมี entitlement (`entitlement: 'none'`) เพื่อไม่เปลี่ยนพฤติกรรมเดิม
3. **Workspace toggle** โดย owner/admin (ตาราง `workspace_modules`, มีอยู่แล้ว)
4. **สิทธิ์ตามบทบาท** (`can(role, permission)`)

กติกา Release 1 (production):
- `MODULES_ENABLED` **ไม่ใส่** ModuleId ของ ERP เลย ผลคือ Hub ปิด หน้า `/` ไป `/journey` เหมือนเดิม ทุกเมนูและทุก route ของ ERP ซ่อน
  และ API ของ ERP ตอบ 404 `module_disabled`
- migration ของ ERP รันได้ตามปกติ (ตารางมีอยู่แต่ว่าง) ไม่กระทบ BOQ
- ฟีเจอร์เดิมของ BOQ (revisions ปุ่ม "ออกฉบับแก้ไข") ทำงานเหมือนเดิมทุกประการเมื่อ `boq-control` ปิด
- dev/staging: ใส่ ModuleId ทั้งหมด และตั้ง `ENTITLEMENTS=open` เพื่อลองได้โดยไม่ต้องให้สิทธิ์

กติกาการปิดโมดูล: ปิดแล้ว **ข้อมูลไม่หาย** ห้ามลบข้อมูลเมื่อปิด เอกสารที่ออกเลขแล้ว (ใบกำกับภาษี ฯลฯ) ห้ามลบในทุกกรณี
