# 03 — สองภาษา ไทย / อังกฤษ (i18n)

สถานะ: ข้อกำหนด · 2026-10-31 · ใช้กับทุกหน้าจอ ERP ใหม่ตั้งแต่ WP แรก และเป็นแผนย้ายหน้าจอเดิม (track I)

## 1. สภาพปัจจุบัน (ตรวจแล้ว)

- ติดตั้ง `next-intl` ^4.8.4 แต่ใช้ **ไม่ผ่าน routing** ไม่มี plugin ใน `next.config.ts` ไม่มี `[locale]` segment
- `src/i18n/config.ts`: `locales = ['th','en']`, `defaultLocale = 'th'`
- `src/i18n/LocaleProvider.tsx`: ผูก `NextIntlClientProvider` กับ `th` เสมอ (import แค่ `./messages/th`), `timeZone="Asia/Bangkok"`, `useAppLocale()` คืน `th` เสมอ
- `src/i18n/messages/{th,en}/{common,nav,app,boqHome}.json` + `index.ts` ต่อภาษา (ราว 70 ข้อความ, en ไม่เคยถูกโหลด)
- ใช้ `useTranslations` แค่ `src/features/boq-home/BoqHomePage.tsx` และ `src/components/AppLayoutUI.tsx`
- `src/app/layout.tsx`: `<html lang="en">` ตายตัว, metadata ไทยตายตัว
- `AppLayoutUI.tsx`: `locale={thTH}` ของ antd และ `dayjs.locale('th')` ระดับโมดูล
- ข้อความไทยตายตัวราว 6,200 บรรทัดใน `features/` + `components/`, ราว 1,700 บรรทัดใน `src/domain` (BOQ template ราว 500 บรรทัด)
- รูปแบบวันที่: หน้าจอส่วนใหญ่ใช้ `th-TH-u-ca-gregory` (ปี ค.ศ.) แต่เอกสาร/หน้าสัญญาจ้างช่วง (`src/features/subcontracting/contracts/logic.ts` `fmtDate`, `src/domain/subcontracting/contract-template.ts` `formatContractDate` ที่มีเทสต์ล็อก `26 ตุลาคม 2569`) ใช้ปี พ.ศ. **โดยตั้งใจ** (เอกสารสัญญา) — **ห้ามแก้** ในงาน ERP (Decisions log D-35)
- `src/features/export/baht-text.ts` อ่านจำนวนเงินเป็นคำไทยเท่านั้น
- error: เว็บแปลรหัสเป็นไทยด้วย `thaiErrorMessage` (`src/features/cloud/api/errors.ts`)
- แจ้งเตือน: backend เก็บ title/body ภาษาไทยที่เรนเดอร์แล้ว

## 2. สถาปัตยกรรม locale (WP-01)

ใช้ next-intl แบบ "without i18n routing" (URL ไม่มี `/th` `/en`):

1. `next.config.ts`: ครอบด้วย `createNextIntlPlugin('./src/i18n/request.ts')` จาก `next-intl/plugin`
2. `src/i18n/request.ts`: `getRequestConfig(async () => { const locale = resolveLocale((await cookies()).get('NEXT_LOCALE')?.value); return { locale, messages: (await import(\`./messages/${locale}\`)).default, timeZone: 'Asia/Bangkok' }; })`
   `resolveLocale` คืน `th` เมื่อค่าไม่ถูกต้อง
3. `src/app/layout.tsx` เป็น async: `const locale = await getLocale(); const messages = await getMessages();`
   `<html lang={locale}>` และ `<NextIntlClientProvider locale={locale} messages={messages} timeZone="Asia/Bangkok">` ครอบ `LocaleProvider`
   `metadata` เปลี่ยนเป็น `generateMetadata()` ที่ใช้ `getTranslations('app')` (ทำเช่นเดียวกันใน `src/app/(vendor)/layout.tsx`)
4. `src/i18n/LocaleProvider.tsx` (client) เหลือหน้าที่: ให้ `useAppLocale()` คืน `{locale, setLocale}` และสลับ antd/dayjs:
   - `setLocale(l)`: เขียน cookie `NEXT_LOCALE=<l>; path=/; max-age=31536000; samesite=lax` → ถ้าล็อกอินอยู่เรียก `PATCH /me/preferences {locale}` → `router.refresh()`
   - export `useAntdLocale()` คืน `th_TH` หรือ `en_US` (`antd/locale/*`) และเรียก `dayjs.locale(l)` เมื่อเปลี่ยน (import `dayjs/locale/th` และ `dayjs/locale/en`)
5. `AppLayoutUI.tsx` และ vendor shell: ลบ `dayjs.locale('th')` ระดับโมดูล ใช้ `locale={useAntdLocale()}` ใน `ConfigProvider`
6. backend (WP-01): `users.locale` (`'th'|'en'`, default `'th'`), `PATCH /me/preferences {locale}` ใน `backend/src/modules/identity/presentation/me.controller.ts`, `GET /me` คืน `locale`
   (เพิ่มใน contract `src/shared/contract/auth.ts`: `userPreferencesSchema`, `updatePreferencesRequestSchema`)
7. หลังล็อกอิน (`CloudRuntime.tsx`): ถ้า `me.locale` ≠ cookie ให้ตั้ง cookie ตาม `me.locale` แล้ว `router.refresh()` (โปรไฟล์ชนะ)
8. ปุ่มสลับภาษา: ใน `src/features/cloud/ui/AccountMenu.tsx` (กลุ่มใหม่ "ภาษา / Language") และใน vendor shell (มุมขวาบน) และในหน้า login/register แบบไม่ล็อกอิน (ใช้ cookie อย่างเดียว)
9. type-safe: `src/i18n/global.d.ts`
   ```ts
   import type th from './messages/th';
   import type { Locale } from './config';
   declare module 'next-intl' { interface AppConfig { Messages: typeof th; Locale: Locale } }
   ```
   ผล: คีย์ที่พิมพ์ผิดไม่ผ่าน `tsc`

หมายเหตุขนาด bundle: ทุก namespace ของภาษาปัจจุบันถูกส่งไปเบราว์เซอร์ ยอมรับได้ในเฟสนี้ ถ้าใหญ่เกินภายหลังให้ใช้ `pick(messages, [...])` ต่อ layout (บันทึกใน Decisions log D-15)

## 4. การตั้งชื่อคีย์และวิธีใช้

- รูปแบบ: `<namespace>.<screenOrComponent>.<element>` เป็น camelCase เช่น `quotations.editor.addSection`, `billing.claim.retentionLabel`
- คีย์ที่ใช้ซ้ำทั้งโมดูล: `<namespace>.actions.*`, `<namespace>.fields.*`, `<namespace>.empty.*`, `<namespace>.confirm.*`
- ปุ่มทั่วไป (บันทึก ยกเลิก ลบ แก้ไข ปิด) ใช้ `common.*` ห้ามซ้ำในโมดูล
- ตัวแปร: ICU `{name}`, พหูพจน์ `{count, plural, one {# item} other {# items}}` (ภาษาไทยใส่ `other` อย่างเดียวได้)
- ห้ามต่อสตริงเป็นประโยค ให้ใช้ตัวแปรใน message เดียว
- ใน component: `const t = useTranslations('quotations');` แล้ว `t('editor.addSection')`; server component ใช้ `getTranslations`
- ข้อความใน antd API (`message.success`, `modal.confirm`, `placeholder`, `aria-label`, `title`) ต้องมาจาก `t()` ทั้งหมด
- enum: `const te = useTranslations('enums'); te(\`quotationVersionStatus.${status}\`)` — ประกาศคีย์ครบทุกค่า
- error: `useErrorMessage()` (`src/features/cloud/api/error-message.ts`, WP-01) แปล `ApiError` → `errors.reasons.<reason>` ถ้ามี `details.reason` ไม่งั้น `errors.codes.<code>`
  `thaiErrorMessage` เดิมคงไว้เป็น wrapper (ภาษาไทย) จนกว่า track I จะย้ายผู้เรียกครบ
- ไฟล์ th และ en ต้องมีคีย์เหมือนกันทุกตัว (`check-parity`) ภาษาอังกฤษต้องเป็นคำแปลจริง ห้ามคัดลอกไทยไปใส่

## 5. การจัดรูปแบบตัวเลข เงิน วันที่ (`src/i18n/format.ts`, WP-01)

| ฟังก์ชัน | th | en |
|---|---|---|
| `formatNumber(v, locale, {min?, max?})` | `Intl.NumberFormat('th-TH-u-nu-latn')` | `Intl.NumberFormat('en-US')` |
| `formatMoney(v, locale)` (2 ตำแหน่งเสมอ ไม่มีสัญลักษณ์) | `1,234.50` | `1,234.50` |
| `formatBaht(v, locale)` | `1,234.50 บาท` | `THB 1,234.50` |
| `formatQty(v, locale)` (สูงสุด 4 ตำแหน่ง ตัดศูนย์ท้าย) | `12.5` | `12.5` |
| `formatPercent(rate, locale, digits=2)` (รับเศษส่วน 0.05) | `5%` | `5%` |
| `formatDate(date, locale)` (`YYYY-MM-DD` หรือ ISO) | `31 ต.ค. 2026` (`th-TH-u-ca-gregory`, `day:'numeric', month:'short', year:'numeric'`) | `31 Oct 2026` (`en-GB`) |
| `formatDateLong(date, locale)` | `31 ตุลาคม 2026` | `31 October 2026` |
| `formatDateTime(iso, locale)` | `31 ต.ค. 2026 14:05` | `31 Oct 2026, 14:05` |
| `formatDocumentDate(date, locale, yearStyle)` | `ce` → `31 ตุลาคม 2026`; `be` → `31 ตุลาคม 2569` (`th-TH-u-ca-buddhist`) | ใช้ ค.ศ. เสมอ (`yearStyle` ถูกละไว้สำหรับ en) |
| `amountInWords(v, locale)` | `bahtText(v)` จาก `src/features/export/baht-text.ts` | `amountInWordsEn(v)` จาก `src/domain/money/amount-in-words.ts` |

- ทุกฟังก์ชันใช้ `timeZone: 'Asia/Bangkok'` สำหรับ ISO timestamp; วันที่ `YYYY-MM-DD` ถูกตีความเป็นวันที่ (ไม่แปลงโซน: ใช้ `timeZone: 'UTC'` กับ `Date.UTC(y, m-1, d)`)
- `useFormat()` คืนชุดฟังก์ชันที่ผูก locale ปัจจุบัน `{ number, money, baht, qty, percent, date, dateLong, dateTime }`
- **UI ใช้ปี ค.ศ. เสมอ** (กติกาเจ้าของ) ปี พ.ศ. ใช้ได้เฉพาะบนเอกสารพิมพ์ภาษาไทยเมื่อ `company_profiles.document_year_style = 'be'`
- ห้ามเรียก `toLocaleString('th-TH')` หรือ `Intl.*` ตรงในโค้ด ERP ใหม่ ให้ผ่าน `format.ts`
- input ตัวเลขยังใช้ antd `InputNumber` (มี handler กันอักขระที่ไม่ใช่ตัวเลขใน `AppLayoutUI`) — ERP ใช้ `MoneyInput` / `QtyInput` ใน `src/features/erp/shared/` (WP-06) ที่ใส่ `precision` และ `formatter` จาก `format.ts`

## 6. ภาษาของเอกสาร (ต่างจากภาษา UI)

- ทุกเอกสารที่ออกให้คนนอก (ใบเสนอราคา สัญญา ใบแจ้งหนี้ ใบกำกับภาษี ใบเสร็จ ใบลดหนี้ VO PO RFQ 50 ทวิ ใบส่งมอบ) มีคอลัมน์ `language` (`'th'|'en'`)
- ค่าเริ่มต้น: `customers.default_doc_language` → `company_profiles.default_doc_language` → `'th'`; ผู้ขาย (PO/RFQ) ใช้ `company_profiles.default_doc_language`
- เปลี่ยนภาษาได้ขณะเป็นร่าง หลัง issue ล็อก (เนื้อหาเอกสารที่ออกแล้วห้ามเปลี่ยน)
- 50 ทวิ: ภาษาไทยเสมอ (แบบฟอร์มกรมสรรพากร) ช่องภาษาอังกฤษไม่มี
- การเรนเดอร์: `src/i18n/document-translator.ts`
  ```ts
  import thDocuments from './messages/th/documents.json';
  import enDocuments from './messages/en/documents.json';
  export function documentTranslator(locale: Locale) {
      return createTranslator({ locale, messages: { documents: locale === 'th' ? thDocuments : enDocuments }, namespace: 'documents' });
  }
  ```
  หน้าพิมพ์ใช้ `documentTranslator(doc.language)` และ `format.ts` ด้วย `doc.language` **ไม่ใช่** `useTranslations`
- ข้อมูลสองภาษาที่ผู้ใช้ป้อน: `name_th`/`name_en` (บริษัท ลูกค้า ผู้ขาย), `desc_th`/`desc_en` (บรรทัดเอกสาร), `label_th`/`label_en` (งวด), `title_th`/`title_en` (หมวด)
  เลือกด้วย `pickLocalized(th, en, locale)` (`src/i18n/format.ts`): en ว่าง → ใช้ th, th ว่าง → ใช้ en
- รายการ BOQ ภาษาอังกฤษ: overlay `src/domain/boq/template.v5.en.ts` (`BOQ_LINES_EN: Record<lineKey, {desc: string}>`, `BOQ_SECTION_TITLES_EN: Record<number, string>`) และ `src/domain/boq/units.ts` (`UNIT_EN: Record<string, string>` ครบทั้ง 14 หน่วยที่ template ใช้จริง: `ตร.ม.` → `sq.m`, `ชุด` → `set`, `กก.` → `kg`, `ลบ.ม.` → `cu.m`, `ม.` → `m`, `เหมา` → `lump sum`, `แผ่น` → `sheet`, `ลบ.ฟ.` → `cu.ft`, `ท่อน` → `length`, `ตัว` → `pc`, `ห้อง` → `room`, `ต้น` → `pc`, `จุด` → `point`, `ม้วน` → `roll`; หน่วยที่ไม่มีใน map ใช้ข้อความไทยเดิม — หาหน่วยทั้งหมดด้วย `grep -o '"unit": "[^"]*"' src/domain/boq/template.v5.ts | sort -u` และหน่วยของ slot rows ใน `src/domain/boq/slots.ts`)
  สร้างใน WP-22 (ใช้ตอนสร้างใบเสนอราคา: `desc_en` = overlay ถ้ามี ไม่งั้นว่าง) ผู้ใช้แก้ `desc_en` เองได้ทุกบรรทัด
  slot rows (เหล็ก ประตูหน้าต่าง) ใช้ฟังก์ชัน `slotLineEn(lineKey, descTh)` (เช่น `เหล็กเส้น DB12` → `Rebar DB12`) ในไฟล์เดียวกัน

## 7. ข้อความจาก server

| ข้อความที่ผู้ใช้พิมพ์ (ชื่อโครงการ หมายเหตุ) | เก็บตามที่พิมพ์ ไม่แปล |
| ป้ายโมดูลใน backend (`MODULE_LABEL`) | คงไว้ (ไทย) ใช้เฉพาะ log/ข้อความเดิม หน้าจอใหม่ใช้ `modules.<id>.label` |

2. **คัดลอกข้อความไทยแบบตรงตัวอักษร** ไปไว้ใน `th/*.json` (Robot e2e ใน `tests/robot/` ใช้ข้อความไทยเป็น locator — ต้องไม่เปลี่ยนแม้แต่ช่องว่าง)
3. แปลอังกฤษใน `en/*.json` พร้อมกัน
4. หนึ่ง WP ต่อหนึ่งกลุ่มไฟล์ (≤ ~25 ไฟล์) ตาม `04-implementation-plan.md` track I
5. ข้อมูลโดเมน (`src/domain/**`) ไม่ย้ายไป JSON ตรง ๆ ให้ทำ overlay ภาษาอังกฤษแบบ keyed (แบบ BOQ overlay §6) แล้วให้ UI เลือกตาม locale
   เครื่องคำนวณใช้ `CalculatorDef.titleEn` (มีอยู่แล้วใน `src/domain/calculators/types.ts`) และเพิ่ม overlay `sections`/`options` ใน I-07
6. หลังย้ายแต่ละกลุ่ม เพิ่ม glob ของกลุ่มนั้นเข้า ESLint rule ห้ามไทย เพื่อไม่ให้ถอยกลับ
7. ลำดับ: เปลือกแอป/บัญชี/ล็อกอิน (I-01) → BOQ release 1 (I-02…I-08) → planning (I-09) → cloud/workforce (I-10, I-11) → subcontracting/vendor (I-12…I-14)
8. ยังไม่เปิดปุ่มสลับภาษาให้ผู้ใช้ production เห็น จนกว่า I-01…I-08 เสร็จ: ปุ่มแสดงเฉพาะเมื่อ env เว็บ `NEXT_PUBLIC_LANGUAGE_SWITCH=1` (WP-01) หรือ `project-hub` active (เงื่อนไขนี้เพิ่มใน WP-16 เพราะ ModuleId `project-hub` เกิดใน WP-03) (Decisions log D-16)
