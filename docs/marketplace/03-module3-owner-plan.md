# โมดูล 3 — เจ้าของงานหาผู้รับเหมาหลัก : แผนระดับกลาง

สถานะ: **แผนทิ้งไว้ ยังไม่เริ่ม** (ร่าง 26 ต.ค. 2026) — ทำหลังโมดูล 1 และ 2 และหลังมีผู้รับเหมาที่ผ่านการคัดกรอง L2 ขึ้นไปในพื้นที่นำร่องจำนวนพอ
flag: `owner-leads` ; ตาราง prefix `ol_` ; ผู้ใช้ใหม่ทั้งฝั่ง (เจ้าของบ้าน) → ความรับผิดและกฎหมายสูงกว่า B2B ต้องมีที่ปรึกษากฎหมายก่อนเปิด

---

## 1. เป้าหมายและคุณค่า
- **เจ้าของบ้าน/เจ้าของงาน**: ได้ "ราคากลาง" จาก BOQ engine ก่อนคุยกับผู้รับเหมา, เทียบข้อเสนอของผู้รับเหมาที่มีประวัติจริงบนรายการเดียวกัน, สัญญาพร้อมงวดจ่ายตามตรวจรับ → ลดเสี่ยงโดนทิ้งงาน/จ่ายเกินงาน
- **ผู้รับเหมา (ฝั่ง A)**: lead ที่มี BOQ พร้อมแล้ว (ไม่ต้องถอดแบบฟรีเพื่อเสนอราคา), แข่งบนความน่าเชื่อถือไม่ใช่ราคาต่ำสุดอย่างเดียว, ได้งานแล้วบริหารต่อด้วยโมดูล 1–2 ทันที → **ช่องทางหาผู้ใช้ฝั่ง A ที่แข็งแรงที่สุด**
- **แพลตฟอร์ม**: success fee / lead fee จากผู้รับเหมา, และข้อมูลความต้องการสร้างบ้านรายพื้นที่

## 2. สิ่งที่ต้องมีก่อน (จากโมดูล 1–2)
- ระดับคัดกรอง **L2 (เอกสารตรวจแล้ว)** และ **L3 (ประวัติข้ามผู้ว่าจ้าง)** ของผู้รับเหมาใช้งานจริง — เจ้าของบ้านต้องเห็นความน่าเชื่อถือที่ระบบยืนยัน ไม่ใช่กรอกเอง
- กลไกแพ็กเกจ/คำเชิญ/ใบเสนอราคา/ตารางเทียบ/สัญญา/งวด/ตรวจรับ จากโมดูล 1 — ใช้ซ้ำโดยเปลี่ยน "ผู้ซื้อ" เป็นเจ้าของบ้าน และ "ซับ" เป็นผู้รับเหมาหลัก
- โหมดจัดหา `open` (ประกาศเปิดรับ) ที่โมดูล 1 ออกแบบช่องไว้
- พาร์ตเนอร์ผู้ตรวจงาน (inspector) และ (ถ้าจะถือเงิน) พาร์ตเนอร์ escrow/e-money ที่มีใบอนุญาต

## 3. ผู้ใช้
| ฝั่ง | ใคร | ทำอะไร |
|---|---|---|
| เจ้าของงาน | เจ้าของบ้าน, เจ้าของที่ดิน, ร้าน/โรงงานเล็ก | ส่งแบบ/ความต้องการ, รับราคากลาง, เปิดรับข้อเสนอ, เทียบ, ทำสัญญา, อนุมัติงวดตามตรวจรับ, ให้คะแนน |
| ผู้รับเหมาหลัก | workspace ที่มี vendor profile L2+ และ trade `general-contractor` | รับ lead, เสนอราคาตามรายการ, ใช้ BOQ ของ lead เป็นโครงการของตัวเองเมื่อได้งาน |
| ผู้ตรวจงาน (optional) | บริษัทตรวจบ้าน/วิศวกรอิสระ | ตรวจรับงวดแทนเจ้าของ (บทบาทใหม่ `inspector` ต่อสัญญา) |
| ทีมงานแพลตฟอร์ม | ผู้ประมาณราคา | ทำ BOQ จากแบบให้เจ้าของ (บริการ) ในช่วงแรกก่อนมี wizard |

## 4. Flow หลัก
```
เจ้าของสร้างคำขอ (ที่ตั้ง, ประเภท/ขนาดบ้าน, แบบ/รูป, งบ, ช่วงเวลา)
   ─► ราคากลาง: (ก) wizard ย่อ: จำนวนชั้น/พื้นที่/ห้องน้ำ/หลังคา → BOQ ประมาณช่วง  (ข) บริการทำ BOQ จากแบบ (ทีมงาน/ผู้รับเหมาพาร์ตเนอร์)
   ─► เปิดรับข้อเสนอ: เชิญผู้รับเหมา L2+ ในรัศมี/จังหวัด (ระบบแนะนำ 3–7 ราย ตามประวัติ trade/ขนาดงาน/คิวว่าง) + เจ้าของเพิ่มรายที่รู้จักได้
   ─► ผู้รับเหมาเสนอราคาตามรายการ BOQ (หรือเหมา) + แผนงาน + ทีม + ผลงาน + เงื่อนไขงวด
   ─► เจ้าของเทียบ: ราคา vs ราคากลาง, ประวัติ L3, งวดที่เสนอ, ระยะเวลา  (ระบบไม่จัดอันดับ "ถูกสุด" เป็นค่าเริ่มต้น)
   ─► นัดคุย/ดูไซต์ → ตกลง → สัญญา (เทมเพลตมาตรฐานผู้บริโภค, งวดตามผลงาน, retention, ประกันผลงาน)
   ─► ระหว่างก่อสร้าง: ผู้รับเหมาส่งเบิกงวด + รูป → ผู้ตรวจ/เจ้าของตรวจรับ → อนุมัติ → (เฟสแรก) เจ้าของจ่ายเอง บันทึกในระบบ / (เฟสหลัง) ปล่อยจาก escrow
   ─► ปิดงาน → ประกันผลงาน → ให้คะแนน → ป้อน L3 ของผู้รับเหมา
```

## 5. สิ่งที่ต่างจากโมดูล 1 (ไม่ใช่แค่สลับบทบาท)
- **ภาษาและความซับซ้อน**: เจ้าของบ้านไม่รู้ศัพท์ BOQ → รายการต้องแสดงเป็น "กลุ่มงานที่เข้าใจได้" (ฐานราก, โครงสร้าง, หลังคา, ผนัง-ฉาบ, พื้น-กระเบื้อง, ไฟฟ้า, ประปา, สี, ประตูหน้าต่าง) และซ่อนรายละเอียดเหล็ก/ปูนไว้ใต้ "ดูรายละเอียด"
- **ความโปร่งใสของราคากลาง**: แสดงเป็นช่วง (±%) ไม่ใช่ตัวเลขเดียว เพื่อไม่ให้ผู้รับเหมาถูกกดด้วยตัวเลขที่ประเมินจากแบบย่อ
- **การคัดกรองเป็นหน้าที่ของแพลตฟอร์ม**: ต้องมี L2 (DBD, ภ.พ.20, ใบอนุญาต, ประกัน) ตรวจโดยทีมงาน และกระบวนการรับเรื่องร้องเรียน/ระงับบัญชี
- **กฎหมายผู้บริโภค**: สัญญารับเหมาก่อสร้างกับผู้บริโภค, ข้อสัญญาที่ไม่เป็นธรรม, PDPA ฝั่งเจ้าของบ้าน; แพลตฟอร์มต้องชัดว่าเป็นตัวกลางข้อมูล ไม่ใช่คู่สัญญา (เว้นแต่จะทำ escrow ซึ่งต้องมีใบอนุญาต)
- **การถือเงิน**: เฟสแรก **ไม่ถือ**; escrow เป็นตัวเลือกเมื่อมีพาร์ตเนอร์ — นี่คือจุดที่ Q-CHANG ทำได้เพราะเป็นบริษัทในเครือ SCG; เราต้องมีพาร์ตเนอร์

## 7. Milestones (หลังโมดูล 2)
| M | เนื้อหา | ประมาณ |
|---|---|---|
| O0 | L2 verification ops (หน้าทีมงานตรวจเอกสาร), L3 track record (สถิติข้าม workspace แบบ opt-in), trade `general-contractor` | 3 สัปดาห์ |
| O1 | คำขอของเจ้าของ + wizard ราคากลาง (map พารามิเตอร์บ้านย่อ → calculator inputs ของ engine → ช่วงราคา) + บริการทำ BOQ จากแบบ (เวิร์กโฟลว์ภายใน) | 3 สัปดาห์ |
| O2 | เปิดรับข้อเสนอ (open mode), ระบบแนะนำผู้รับเหมา, ข้อเสนอ, ตารางเทียบแบบผู้บริโภค, นัดหมาย | 3 สัปดาห์ |
| O3 | สัญญาผู้บริโภค, งวด/ตรวจรับ (บทบาท inspector), ร้องเรียน, ให้คะแนน → L3, ส่งโครงการเข้า workspace ผู้รับเหมา (โมดูล 1–2 ต่อทันที) | 3 สัปดาห์ |
| O4 | escrow ผ่านพาร์ตเนอร์ (ถ้าพร้อม), เว็บหน้าแรกสำหรับเจ้าของบ้าน, SEO/เนื้อหา, การตลาดพื้นที่นำร่อง | 2+ สัปดาห์ |

## 8. คำถามเปิด
- wizard ราคากลางแม่นพอไหมสำหรับบ้านที่ไม่มีแบบ — ต้องทดสอบกับโครงการตัวอย่างใน oracle tests ก่อน (ความคลาดเคลื่อน ±15% จึงจะกล้าแสดง)
- ค่าธรรมเนียมเก็บจากผู้รับเหมาเมื่อได้งาน (success fee) เสี่ยงให้เลี่ยงระบบ — ทางเลือก: ค่า lead คงที่ต่อข้อเสนอ + subscription
- ใครรับผิดชอบเมื่อผู้รับเหมาที่ระบบคัดกรองทิ้งงาน — ต้องมีข้อตกลงใช้งานและประกันของพาร์ตเนอร์ก่อนเปิด
- ขอบเขตแรก: บ้านสร้างใหม่ 1–2 ชั้นเท่านั้น (ตรงกับ engine) ไม่รับรีโนเวต
