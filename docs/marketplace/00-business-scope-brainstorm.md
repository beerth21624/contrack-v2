# ConTrack เฟสถัดไป — เครือข่ายจัดหา (ซับคอนแทรค · ร้านวัสดุ · เจ้าของงาน)

สถานะ: **brainstorm / ตีสโคปธุรกิจ** ยังไม่ลงมือทำ (26 ต.ค. 2026)
ต่อยอดจาก: ระบบ BOQ ปัจจุบัน (32 หมวด + เครื่องคำนวณ + Man-Day / S-Curve / CashFlow + workspace/ทีม)

---

## 0. สรุปใน 1 หน้า

**วิทยานิพนธ์ของธุรกิจ:** ระบบ BOQ ที่มีอยู่คือ "ต้นทาง" ของทุกการซื้อในโครงการ — มันรู้ว่าโครงการนี้ต้องใช้
*งานอะไร ปริมาณเท่าไร สเปกอะไร ต้องเสร็จสัปดาห์ไหน และเงินจะเข้า-ออกเมื่อไร*
คู่แข่งทุกรายในไทย (BUILK RFQ, iCONS, กลุ่ม Facebook, LINE) เริ่มจาก "ช่องว่างให้พิมพ์ว่าต้องการอะไร"
เราเริ่มจาก BOQ ที่คำนวณเสร็จแล้ว → กดปุ่มเดียวได้ "แพ็กเกจงานจ้างช่วง" และ "ใบขอราคาวัสดุ" ที่มีปริมาณ/สเปก/กำหนดส่ง/งวดจ่ายครบ

**ปัญหาที่แก้ (ต้นเหตุขาดทุนของผู้รับเหมา SME):**

| ต้นเหตุขาดทุน | ระบบเดิมแก้ | เฟสใหม่แก้ |
|---|---|---|
| ประมาณราคาผิด | ✅ BOQ จากเครื่องคำนวณ | — |
| จ้างซับแพงกว่าที่ประเมิน / สโคปไม่ตรงกัน | — | เทียบราคาซับกับค่าแรงใน BOQ แถวต่อแถว |
| ซับทิ้งงาน / งานไม่ได้คุณภาพ | — | คัดกรองก่อนจ้าง + งวดจ่ายตามผลงาน + ประวัติบนแพลตฟอร์ม |
| ซื้อวัสดุแพง / ส่งไม่ทันงาน / ขาดเครดิต | — | RFQ หลายร้านจากรายการวัสดุ BOQ + กำหนดส่งตาม S-Curve |
| กระแสเงินสดสะดุด (จ่ายซับ/ร้านก่อนเก็บงวดได้) | ✅ CashFlow (แผน) | ผูกจ่ายซับ/PO เข้าแผน + (เฟสหลัง) พาร์ตเนอร์สินเชื่อ |

**ลำดับเฟสที่แนะนำ:**
1. **Phase 1 — จ้างช่วงจาก BOQ (ใช้ได้แม้ไม่มีเครือข่าย)**: แพ็กเกจงาน → ส่งขอราคาให้ทีมช่างของตัวเอง (ลิงก์/LINE) → ตารางเทียบราคา → ตกลงจ้าง → สัญญา/งวด/เงินประกันผลงาน
2. **Phase 2 — เครือข่ายเปิด**: โปรไฟล์ซับ + ระดับการคัดกรอง + กระดานประกาศงาน + คะแนนจากงานที่จบจริง; ขอราคาวัสดุหลายร้าน
3. **Phase 3 — ข้อมูลและการเงิน**: ดัชนีราคาจริงรายพื้นที่ป้อนกลับ BOQ, เครดิต/สินเชื่อผ่านพาร์ตเนอร์, ฝั่งเจ้าของบ้านหาผู้รับเหมาหลัก

## 1. วงการจริงทำกันอย่างไร (จากการค้นคว้า)

### 1.1 ผู้รับเหมา SME ไทย (ตลาดหลักของเรา)
- ผู้รับเหมานิติบุคคลในไทย ~108,000 ราย รายใหญ่แค่ ~700 ราย ที่เหลือกลาง-เล็ก (วิจัยกรุงศรี, ข้อมูลปี 2565); มูลค่าธุรกิจรับเหมา ~1.4 ล้านล้านบาท ปี 2566 และปิดกิจการ 2,306 รายในปีเดียว — ตลาดใหญ่แต่ตายง่าย
- การหาซับ: **ปากต่อปาก, ทีมช่างประจำ, กลุ่ม Facebook/LINE, ประกาศใน iCONS** ไม่มีการคัดกรองเป็นทางการ ดูผลงานจากรูปในมือถือ โทรถาม
- วิธีคิดราคา: **ค่าแรงเหมาต่อหน่วยงาน** (ตร.ม. ก่ออิฐ/ฉาบ/ปูกระเบื้อง/มุงหลังคา, จุดไฟ-ประปา, เมตรท่อ) หรือเหมาทั้งหมวด หรือรายวัน; แยกชัดว่า "ค่าแรงอย่างเดียว" หรือ "รวมของ" (labour-only vs supply-and-install) — ตรงกับที่ BOQ Home แยกคอลัมน์วัสดุ (I) กับค่าแรง (K) อยู่แล้ว
- การจ่าย: **งวดงาน** ตามความคืบหน้า, หัก **เงินประกันผลงาน (retention) 5–10%** ของแต่ละงวด คืนเมื่อตรวจรับ/หมดระยะประกัน 6–24 เดือน
- ความเจ็บปวดที่เจอซ้ำ: ซับทิ้งงาน (มักเพราะเลือกราคาต่ำสุด + ผู้รับเหมาบริหารไม่ดี), ผู้รับเหมาหลักเก็บเงินจากเจ้าของงานไม่ได้แล้วจ่ายซับไม่ได้ (ข่าวชลบุรี 2567 ซับต้องปลดคนงานหลายร้อยคน), ต้องสำรองค่าวัสดุ/ค่าแรงก่อนได้เงินงวด

### 1.2 ผู้รับเหมากลาง-ใหญ่ / งานทางการ
- **ทะเบียนผู้รับเหมาช่วง (vendor list)**: ซับต้องยื่นเอกสารขึ้นทะเบียนก่อน — หนังสือรับรองบริษัท, ภ.พ.20, ทุนจดทะเบียน, ผลงานย้อนหลัง, ใบอนุญาตประกอบวิชาชีพ (กว./สถาปนิก) ตามประเภทงาน, ประกัน, ความปลอดภัย
- **Pre-qualification (PQ / PQQ / SAQ)**: แบบสอบถามประเมินตนเองก่อนให้สิทธิ์เสนอราคา; ภาครัฐสหรัฐฯ/อังกฤษกำหนดเป็นกฎ (ต้องผ่าน PQ ก่อนยื่น bid, มีอายุ 1 ปี) ครอบคลุม: ประเภทงาน, ใบอนุญาต, กำลังคน, หัวหน้างาน, เครื่องมือ, งานที่รับอยู่ปัจจุบัน, คำถามเฉพาะสโคป
- **ขั้นตอนประมูลซับ**: แพ็กเกจงาน (scope + แบบ + BOQ) → เชิญเสนอราคา (ITB/RFQ) → รับราคาในแบบฟอร์มเดียวกัน → **bid leveling** (ตารางเทียบแถวต่อแถว ปรับสโคปให้เท่ากัน ตัด outlier) → ต่อรอง → ตกลงจ้าง → สัญญาจ้างช่วง → งวด/retention/ประกันความชำรุด
- ภาครัฐไทยใช้ e-bidding (e-GP) สำหรับผู้รับเหมาหลัก — ซับของงานรัฐยังเป็นการเจรจาเอกชน

### 1.3 ตอบคำถาม "ต้องประมูลไหม"
ไม่จำเป็นเสมอ และ **ไม่ควรบังคับ**: SME ส่วนใหญ่เจรจากับทีมที่รู้จัก; การประมูลเอาราคาต่ำสุดคือสาเหตุหนึ่งของการทิ้งงาน
ระบบจึงต้องรองรับ **3 วิธีจัดหา** ในหน้าเดียวกัน (ดู §3.2): จ้างตรงทีมประจำ / ขอราคาเทียบ 3–5 ราย / ประกาศเปิดรับ
Reverse auction (ลดราคาแข่งกันแบบสด) — **ไม่ทำ** อย่างน้อยในปีแรก

### 1.4 แพลตฟอร์มที่มีอยู่ และช่องว่าง

| ราย | ทำอะไร | ช่องว่างที่เราแทรกได้ |
|---|---|---|
| **BUILK ONE** (Builk ERP, Pojjaman, Yello) | ERP คุมต้นทุนรายโปรเจ็ค + RFQ/ขายวัสดุ (Yello) รวมออเดอร์ SME ต่อรองโรงงาน; มี SCG/กรุงศรีลงทุน | ไม่มี marketplace ซับคอนแทรค, RFQ วัสดุต้องพิมพ์เอง ไม่ได้ generate จากปริมาณที่คำนวณ |
| **iCONS** | ประกาศความต้องการวัสดุ/ผู้รับเหมา + ฐานข้อมูลโครงการ | เป็น classifieds ไม่มี workflow เทียบราคา/สัญญา/งวด |
| **Q-CHANG (SCG/Nexter), Fixzy** | B2C ช่างซ่อมบ้าน จ่ายผ่านแพลตฟอร์มก่อนเริ่มงาน | ไม่ใช่ B2B งานก่อสร้างใหม่; ยืนยันว่าโมเดล "แพลตฟอร์มถือเงิน + คัดกรองช่าง" ทำได้ในไทย |
| **NocNoc, OneStockHome, Alangkan Thai** | e-commerce วัสดุ (B2C/B2B บางรายมีเครดิตเทอม) | ขายของ ไม่ได้ช่วยซื้อ "ตามรายการ BOQ" และไม่เทียบหลายร้าน |
| **BuildingConnected (Autodesk), Downtobid** (สหรัฐฯ) | bid packages, ITB, bid leveling, เครือข่ายซับ 1M+, วิเคราะห์ความเสี่ยง (TradeTapp) | บทเรียน: ซับจำนวนมาก "ไม่ยอมกรอกในระบบ ส่งราคาทางอีเมลแทน" → ฝั่งซับต้องง่ายระดับ LINE |
| **Avetta / ISNetworld / Constructionline / Achilles** | บริการ prequalification + SAQ แบบสมัครสมาชิก | หนักเกินไปสำหรับ SME ไทย → ทำ "คัดกรองเป็นขั้น" แทน (§3.3) |
| **Doxa (SG), Riverchain (HK)** | สินเชื่อซัพพลายเชน: ผู้รับเหมาหลักอนุมัติงวดในระบบ → ซับรับเงินก่อนกำหนด | นี่คือโมเดลรายได้ปลายทาง (Phase 3) ที่ต้องมีข้อมูลงวด/การอนุมัติบนแพลตฟอร์มก่อน |

**ช่องว่างที่ยังไม่มีใครทำในไทย:** จัดหาซับและวัสดุ **จาก BOQ ที่มีโครงสร้าง** + เก็บ "ประวัติจริง" (งานที่จบ, ตรงเวลา, งานแก้, จ้างซ้ำ) เป็นข้อมูลคัดกรอง B2B + ผูกงวด/เงินประกันผลงานไว้ในระบบเดียว

## 2. ผู้ใช้ (4 ฝั่ง) และคุณค่าที่แต่ละฝั่งได้

| ฝั่ง | ใครบ้าง | ได้อะไร | ทำไมจะมา |
|---|---|---|---|
| **A. ผู้ซื้องาน** (ฐานผู้ใช้ปัจจุบัน) | ผู้รับเหมาหลัก SME, บริษัทรับสร้างบ้าน, ผู้พัฒนาโครงการรายย่อย, โฟร์แมน/ผู้ประมาณราคา | หาซับ/ร้านได้เร็วขึ้น, ราคาเทียบกับ BOQ ทันที, ลดเสี่ยงทิ้งงาน, บริหารงวดจ่ายและ retention ไม่หลุด | ใช้ BOQ อยู่แล้ว ปุ่ม "ส่งขอราคา" อยู่ตรงหน้า |
| **B. ซับคอนแทรค / ทีมช่าง** | ทีมเสาเข็ม, โครงสร้าง, ก่ออิฐ-ฉาบ, หลังคา, ฝ้า, กระเบื้อง, สี, ไฟฟ้า, ประปา, อลูมิเนียม, ถมดิน-รื้อถอน | งานใหม่โดยไม่ต้องรอคนรู้จัก, สโคป/ปริมาณชัดก่อนเสนอราคา (ไม่ต้องถอดแบบเอง), หลักฐานงวด/ยอดค้างชัด, โปรไฟล์ผลงานที่ยืนยันแล้วใช้หางานต่อ | ถูกเชิญโดยผู้รับเหมาที่ใช้ระบบ (ไม่ต้องสมัครก่อนก็ตอบราคาได้) |
| **C. ร้านวัสดุ / ผู้แทนจำหน่าย / โรงงาน** | ร้านวัสดุท้องถิ่น, ตัวแทนปูน-เหล็ก-กระเบื้อง-สี, ผู้ผลิตพื้นสำเร็จรูป/เสาเข็ม | ลูกค้า B2B พร้อมรายการ-ปริมาณ-กำหนดส่งชัด, ตัดสินใจให้เครดิตได้จากข้อมูลโครงการ | lead ที่พร้อมซื้อ ไม่ใช่คนถามราคาเล่น |
| **D. เจ้าของงาน** (เฟสหลัง) | เจ้าของบ้าน, เจ้าของที่ดิน/ร้าน/โรงงานเล็ก | ราคากลางจาก BOQ engine, เทียบผู้รับเหมาที่มีประวัติจริง, งวดจ่ายตามตรวจรับ | ความโปร่งใส + ลดเสี่ยงโดนทิ้งงาน |

หลัก: **เริ่มจาก A → B ก่อน** (A มีอยู่แล้ว, B ถูกดึงมาผ่าน A), ตามด้วย C, แล้วค่อย D

## 3. โมดูล 1 — หาซับคอนแทรค ("จ้างช่วง")

### 3.1 แพ็กเกจงาน (Work Package) — หน่วยพื้นฐาน
สร้างจาก BOQ โดยตรง:
- เลือก **หมวด BOQ** (0–31) หรือเลือกแถวเฉพาะ → ระบบดึง รายการ, หน่วย, ปริมาณ (สุทธิและรวมเผื่อ), ค่าแรง/หน่วยที่ประเมินไว้ (ซ่อนจากซับได้), สเปกจากเครื่องคำนวณ (เช่น ขนาดเหล็ก, ชนิดกระเบื้อง, รอบสี), แบบ/ไฟล์แนบ
- เลือก **รูปแบบจ้าง**: ค่าแรงอย่างเดียว (ผู้รับเหมาซื้อของเอง) / รวมวัสดุ / รวมวัสดุบางรายการ — เพราะ BOQ แยกวัสดุ-ค่าแรงอยู่แล้ว ทำได้ทันที
- **กำหนดเวลา** ดึงจาก S-Curve (สัปดาห์เริ่ม-จบของหมวด) และ **งวดจ่ายที่เสนอ** ดึงจาก CashFlow / Man-Day (งบของหมวด)
- เงื่อนไขมาตรฐาน: เงินประกันผลงาน %, ระยะประกัน, ค่าปรับล่าช้า, ใครจัดหาน้ำ-ไฟ-ที่พัก (ผูกกับหมวด 2–3 ใน BOQ), ความปลอดภัย
- แพ็กเกจที่พบบ่อยควรมี **เทมเพลต**: "งานโครงสร้างทั้งหมด (หมวด 5–14)", "ก่ออิฐ+ฉาบ (17–18)", "ระบบไฟฟ้า (26 + ท่อร้อยสาย/สายไฟ)", "ระบบประปา-สุขาภิบาล (27 + ท่อน้ำดี/น้ำทิ้ง)", "หลังคา (15–16)", "งานสถาปัตย์ภายใน (19–23, 25)"

### 3.2 วิธีจัดหา 3 แบบ (เลือกต่อแพ็กเกจ)
1. **จ้างตรงทีมประจำ** — เลือกจากทะเบียนซับของ workspace ตัวเอง ส่งแพ็กเกจให้ยืนยันราคา/คิว → ไปขั้นสัญญาเลย (ใช้ได้ตั้งแต่วันแรก ไม่ต้องมี marketplace)
2. **ขอราคาเทียบ (RFQ)** — เชิญ 3–5 ราย จากทะเบียนตัวเอง + แนะนำจากเครือข่าย (เฟส 2) กำหนดวันปิดรับ ซับเห็นแค่แพ็กเกจของตัวเอง ไม่เห็นราคากันและกัน
3. **ประกาศเปิดรับ (Open bid)** — โพสต์ขึ้นกระดานงาน กำหนดระดับคัดกรองขั้นต่ำ (§3.3) พื้นที่ และวันปิดรับ (เฟส 2)

### 3.3 การคัดกรอง — "SAQ แบบเป็นขั้น" ที่เหมาะกับไทย
ไม่ใช้แบบสอบถาม 60 ข้อแบบ Avetta แต่ให้ความน่าเชื่อถือ **สะสมเป็นระดับ** และให้ผู้ซื้อกำหนดขั้นต่ำต่อแพ็กเกจ:

| ระดับ | สิ่งที่ยืนยัน | ใครตรวจ |
|---|---|---|
| L0 ติดต่อได้ | เบอร์โทร/LINE ยืนยัน OTP, ชื่อทีม, ประเภทงานที่รับ, จังหวัดที่รับงาน | อัตโนมัติ |
| L1 โปรไฟล์งาน | ขนาดทีม (ช่าง/คนงาน), ผลงาน 3 งานพร้อมรูป-ที่ตั้ง-ปีที่ทำ, อัตราค่าแรงอ้างอิงต่อหน่วย, เครื่องมือหลัก, เดือนที่ว่าง | ตนเอง (self-assessment) + ผู้ซื้อที่เคยจ้างกดยืนยันได้ |
| L2 เอกสารธุรกิจ | บุคคลธรรมดา: บัตร ปชช.; นิติบุคคล: หนังสือรับรอง DBD, ภ.พ.20, ประกันสังคม; ใบอนุญาต กว./ช่างไฟฟ้า (พรบ.ส่งเสริมพัฒนาฝีมือแรงงาน) ตามประเภทงาน; ประกันอุบัติเหตุ | ทีมงานแพลตฟอร์มตรวจ (คิดค่าตรวจได้) |
| L3 ประวัติบนแพลตฟอร์ม | จำนวนแพ็กเกจที่จบ, ตรงเวลา %, รายการแก้ไข (defect) ต่อแพ็กเกจ, อัตราถูกจ้างซ้ำ, ข้อพิพาท, งานที่รับอยู่ตอนนี้ (กำลังรับงานเกินตัวไหม) | ระบบสร้างจากข้อมูลจริง แก้ไม่ได้ |

หลักสำคัญ: **L3 คือ moat** — ได้มาจากงานที่ผ่านระบบงวด/ตรวจรับจริง คู่แข่งก๊อปไม่ได้
คำถามเฉพาะสโคป (scope-specific) แนบไปกับแพ็กเกจ เช่น งานโครงสร้าง: "มีวิศวกรคุมงานไหม", งานไฟฟ้า: "มีใบอนุญาตช่างไฟฟ้าภายในอาคารกี่คน"

### 3.4 ฝั่งซับเสนอราคา — ต้องง่ายกว่าตอบ LINE
- รับลิงก์ทาง LINE/SMS เปิดได้โดยไม่ต้องสมัคร (สมัครเมื่อจะส่งราคา: เบอร์ + OTP)
- เห็นรายการ-ปริมาณ-หน่วย-แบบ ชัดเจน (ไม่ต้องถอดแบบ) กรอก **ราคาต่อหน่วยแถวต่อแถว** หรือ **เหมาทั้งแพ็กเกจ** ได้ทั้งสองแบบ; ช่อง "ไม่รวม/ข้อยกเว้น", จำนวนวันที่ใช้, วันที่เริ่มได้, จำนวนคน
- แนบรูปผลงานจากมือถือ, ส่งราคาซ้ำได้ (เก็บทุกเวอร์ชัน)
- บทเรียนจาก BuildingConnected: ถ้ากรอกยาก ซับจะส่งราคาทางอื่น → ฝั่งผู้ซื้อต้อง **กรอกแทนซับได้** (บันทึกราคาที่ได้ทางโทรศัพท์) เพื่อให้ตารางเทียบครบ

### 3.5 ตารางเทียบราคา (Bid leveling)
- คอลัมน์ต่อซับ แถวต่อรายการ BOQ; คอลัมน์แรกคือ **ค่าแรงที่ประเมินใน BOQ** → แสดง % ต่าง, ไฮไลต์แถวที่ต่างเกินเกณฑ์, แถวที่ซับไม่ได้ตีราคา (สโคปไม่ครบ)
- ปรับให้เทียบได้ (normalize): เติมรายการที่ซับหนึ่งไม่รวม ด้วยราคาประเมิน เพื่อเทียบ "ราคาเสมือนครบสโคป"
- คะแนนรวมไม่ใช่แค่ราคา: ราคา / ระดับคัดกรอง / คิวว่างตรงแผน / ระยะทาง / ประวัติ — ผู้ซื้อตั้งน้ำหนักเอง (ค่าเริ่มต้นแนะนำ)
- ปุ่ม "ต่อรอง" ส่งข้อความกลับเฉพาะราย, "ตกลงจ้าง" → ไปขั้นสัญญา; ซับที่ไม่ได้รับแจ้งผลอัตโนมัติ (รักษาความสัมพันธ์)

### 3.6 สัญญา งวดงาน และเงินประกันผลงาน
- สร้าง **สัญญาจ้างช่วง** จากแพ็กเกจ + ราคาที่ตกลง (เทมเพลตภาษาไทย ปรับแก้ได้ ส่งออก PDF ลงนามนอกระบบหรือ e-sign เฟสหลัง)
- **งวดจ่าย** ผูกกับความคืบหน้า (เช่น 30/40/30 หรือรายสัปดาห์ตามแผน) ระบบคำนวณ retention อัตโนมัติ (5–10%) และบันทึก **สมุดเงินประกันผลงาน** ต่อซับ: ยอดหัก, วันครบกำหนดคืน, สถานะ
- **ใบเบิกงวด (progress claim)**: ซับขอเบิก → ผู้ซื้อ/โฟร์แมนตรวจรับด้วย checklist ต่อหมวด (ใช้ชุดเดียวกับที่หน้า BOQ มี) → อนุมัติ → บันทึกจ่าย (ระบบ **ไม่ถือเงิน** ในเฟส 1–2 แค่บันทึก)
- ผลสะท้อนกลับ: จ่ายซับจริง vs ค่าแรงใน BOQ → **ต้นทุนจริงเทียบประมาณการ** ต่อหมวด (นี่คือ feature ที่ Builk ขายเป็นหลัก แต่เราได้มาฟรีจากการจัดหา)
- จบแพ็กเกจ → ให้คะแนนสองทาง (ผู้ซื้อให้ซับ: คุณภาพ/เวลา/สื่อสาร; ซับให้ผู้ซื้อ: จ่ายตรงเวลา) → ป้อน L3

## 4. โมดูล 2 — หาร้านวัสดุ ("ขอราคาวัสดุ")

### 4.1 รายการวัสดุจาก BOQ → ล็อตซื้อ
- ระบบมีปริมาณวัสดุรวมเผื่อทุกแถวอยู่แล้ว (คอลัมน์ H) + ตารางสรุปวัสดุงานโครงสร้าง → จัดเป็น **ล็อตซื้อตามช่วงงาน**: ล็อตโครงสร้าง (เหล็ก/ปูน/หิน/ทราย/ไม้แบบ/ลวด), ล็อตผนัง (อิฐ/ปูนก่อ-ฉาบ), ล็อตหลังคา, ล็อตผิว (กระเบื้อง/กาว/ยาแนว), ล็อตสี, ล็อตไฟฟ้า, ล็อตประปา-สุขภัณฑ์
- **วันต้องการของ** ดึงจาก S-Curve (สัปดาห์เริ่มของหมวด ลบ lead time) → ร้านเห็นว่าต้องส่งเมื่อไร ผู้ซื้อไม่ต้องสต็อกเองเร็วเกิน
- ระบุ **ยี่ห้อ/เกรดที่รับได้** (เทียบเท่า) เพื่อให้ร้านเสนอของแทนได้

### 4.2 ขอราคาหลายร้านและเทียบ
- ส่ง RFQ ให้ร้านในพื้นที่จัดส่ง (ร้านประจำของตัวเอง + ร้านในเครือข่าย) ร้านตอบในแบบฟอร์มเดียว: ราคาต่อหน่วย, ค่าส่ง, ราคามีผลถึงวันไหน, ขั้นต่ำ, **เครดิตเทอม** (เงินสด / 30 / 60 วัน), ของแทน
- ตารางเทียบ: **ราคาถึงหน้างานต่อหน่วย** (รวมส่ง) เทียบกับราคาวัสดุใน BOQ (คอลัมน์ I) → เห็นทันทีว่าซื้อถูกหรือแพงกว่าที่ประเมิน; แยกซื้อคนละร้านต่อรายการได้
- **ใบสั่งซื้อ (PO)** + ตารางส่งของ + รับของ (GRN) จากมือถือหน้างาน → ค่าวัสดุจริงต่อหมวด (ต้นทุนจริง vs ประมาณการ ฝั่งวัสดุ)

### 4.3 ฝั่งร้าน
- โปรไฟล์ร้าน: พื้นที่ส่ง, หมวดสินค้า, ยี่ห้อที่มี, นโยบายเครดิต, รถส่ง
- รับ RFQ ทาง LINE OA/อีเมล ตอบจากมือถือได้ ไม่ต้องมี ERP
- เห็นข้อมูลที่ช่วยตัดสินใจให้เครดิต: ประวัติการซื้อ/จ่ายบนแพลตฟอร์มของผู้ซื้อ, แผนกระแสเงินสดของโครงการ (ถ้าผู้ซื้อยอมเปิด) → เครดิตเทอมคือสิ่งที่ผู้รับเหมา SME ต้องการที่สุดจากร้าน

### 4.4 ผลพลอยได้: ดัชนีราคาจริง (Phase 3)
ทุกใบเสนอราคา/PO = จุดข้อมูลราคาจริงรายพื้นที่รายเดือน → ป้อนกลับเป็น "ราคาแนะนำ" ในคอลัมน์ I/K ของ BOQ (ตอนนี้เป็นราคาจาก Excel v5 ตายตัว) → ประมาณราคาแม่นขึ้นเรื่อย ๆ และเป็นข้อมูลที่ขายได้ (ร้าน/โรงงาน/ธนาคาร)

## 5. โมดูล 3 (เฟสหลัง) — เจ้าของงานหาผู้รับเหมาหลัก

- เจ้าของบ้านอัปโหลดแบบ/บอกขนาด → ทีมเรา (หรือ wizard แบบย่อ) ทำ BOQ ด้วย engine เดิม → ได้ **ราคากลาง**
- เชิญผู้รับเหมาที่ผ่านระดับคัดกรองในพื้นที่เสนอราคาตามรายการเดียวกัน → เจ้าของเทียบกับราคากลาง (ไม่ใช่แค่ถูกสุด)
- สัญญา + งวดตามตรวจรับ (พาร์ตเนอร์ผู้ตรวจบ้าน) ผู้รับเหมาที่ได้งานใช้ ConTrack ต่อทันที → นี่คือ **ช่องทางหาผู้ใช้ฝั่ง A** ที่แข็งแรงที่สุด
- ทำหลังสุดเพราะต้องการ (1) ซัพพลายผู้รับเหมาที่คัดกรองแล้ว (2) การถือเงิน/escrow ซึ่งต้องมีพาร์ตเนอร์ที่มีใบอนุญาต (3) ภาระความรับผิดสูงกว่า B2B

## 7. ไปตลาดอย่างไร (GTM) และตัวชี้วัด

**แคบก่อน:** บ้านพักอาศัย 1–2 ชั้น (สิ่งที่ BOQ 32 หมวดครอบคลุม) ในพื้นที่เดียวที่เรามีคนรู้จัก (กทม.-ปริมณฑล หรือจังหวัดที่ผู้ใช้ปัจจุบันอยู่)
**ไม่มี cold start:** เฟส 1 ให้ผู้รับเหมา import "ทีมช่างประจำ" ของตัวเองเป็นทะเบียนส่วนตัว → ซับถูกดึงเข้าระบบผ่านลิงก์ขอราคา → เมื่อซับคนเดียวถูกเชิญจากผู้รับเหมา 2 รายขึ้นไป เครือข่ายเกิดเอง
**ช่องทาง:** ผู้ใช้ BOQ ปัจจุบัน, กลุ่ม Facebook/LINE ผู้รับเหมา, ร้านวัสดุท้องถิ่น (ให้ร้านชวนลูกค้าผู้รับเหมา), งาน FutureBuild Asia, สมาคมผู้รับเหมา/ธุรกิจรับสร้างบ้าน

**ตัวชี้วัดต่อเฟส**
- เฟส 1: % โครงการที่สร้างแพ็กเกจอย่างน้อย 1; จำนวนซับที่ตอบราคาต่อแพ็กเกจ (เป้า ≥ 2); เวลาจากส่ง RFQ → ตกลงจ้าง; % ของมูลค่า BOQ ที่จัดหาผ่านระบบ; retention ที่บันทึกในระบบ
- เฟส 2: ซับที่ L1+ ต่อประเภทงานต่อจังหวัด; อัตราได้ราคาจากซับ "นอกทะเบียนตัวเอง"; ร้านที่ตอบ RFQ ภายใน 48 ชม.; ต้นทุนจริง vs ประมาณการ (ต่างกี่ %)
- เฟส 3: ยอดสินเชื่อที่ปล่อยผ่านพาร์ตเนอร์, ความแม่นของราคาแนะนำ, lead เจ้าของบ้าน → สัญญา

## 8. ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| คุยกันนอกระบบหลังเจอกัน (disintermediation) | ไม่เก็บ % จากค่าจ้าง; คุณค่าอยู่ที่สัญญา/งวด/retention/ประวัติ ซึ่งทั้งสองฝ่ายอยากมีหลักฐาน |
| ซับไม่ใช้แอป | LINE-first, ตอบราคาโดยไม่ต้องสมัคร, ผู้ซื้อกรอกแทนได้ |
| ข้อมูลคัดกรองปลอม | L2 ตรวจเอกสารจริง (DBD, OTP), L3 สร้างจากธุรกรรมเท่านั้น, ผู้ซื้อรายอื่นกดยืนยันผลงานได้ |
| กฎหมาย: แพลตฟอร์มเป็นคู่สัญญาหรือไม่, PDPA, ถือเงิน | ตำแหน่ง = เครื่องมือ/ตลาด ไม่ใช่คู่สัญญา (ข้อตกลงใช้งานชัด); ไม่ถือเงินจนกว่าจะมีพาร์ตเนอร์ที่มีใบอนุญาต (e-money/escrow); PDPA ทำตั้งแต่ออกแบบ (ซับคือเจ้าของข้อมูลโปรไฟล์) |
| งานไม่ตรงกับ BOQ 32 หมวด (อาคารพาณิชย์, งานระบบใหญ่) | เฟสแรกจำกัดบ้านพักอาศัย; แพ็กเกจแบบ "กรอกเอง" ไว้รองรับ |
| ผู้รับเหมาเลือกราคาต่ำสุดแล้วโดนทิ้งงานอยู่ดี | ตารางเทียบแสดงราคา "ต่ำผิดปกติ" เทียบ BOQ เป็นคำเตือน ไม่ใช่ข้อได้เปรียบ; คะแนนรวมถ่วงน้ำหนักประวัติ |

```
 │           └── Quote[] → PurchaseOrder[] → Delivery[] (GRN)
 ├── VendorList (ทีมช่างประจำ / ร้านประจำ)  — ส่วนตัวของ workspace
 └── (ข้าม tenant) Vendor profile + Tier L0–L3 + TrackRecord  — ของซับ/ร้านเอง (PDPA: เจ้าของข้อมูลคือเขา)
```
- หมวด BOQ 0–31 = **taxonomy ประเภทงาน** ของซับโดยธรรมชาติ (เสาเข็ม, โครงสร้าง, ก่ออิฐ-ฉาบ, หลังคา, ฝ้า, กระเบื้อง, สี, อลูมิเนียม, ไฟฟ้า, ประปา) ไม่ต้องคิดใหม่
- `computeProject()` ที่เป็น pure function ใช้สร้าง snapshot ของแพ็กเกจ (ปริมาณ ณ วันส่ง RFQ) และตรวจว่าหลัง revision ปริมาณเปลี่ยนไหม → แจ้งซับ
- ต้นทุนจริง (จ่ายซับ + PO) เทียบกับ J/L ของ BOQ = หน้ารายงานใหม่ "ประมาณการ vs จริง" ต่อหมวด

## 10. สิ่งที่ต้องตัดสินใจก่อนเริ่ม Phase 1

1. **พื้นที่และประเภทงานตั้งต้น** — จังหวัด/ภูมิภาคไหน, เริ่มจากซับ 3–4 ประเภทไหน (แนะนำ: โครงสร้าง, ก่ออิฐ-ฉาบ, ไฟฟ้า, ประปา — เป็นหมวดที่ค่าแรงสูงสุดใน BOQ)
2. **เครือข่ายที่มีอยู่** — มีผู้รับเหมา/ซับ/ร้านที่พร้อมเป็นผู้ใช้นำร่องกี่ราย (seed supply)
3. **ถือเงินหรือไม่** — แนะนำ "ไม่" ในเฟส 1–2 (บันทึกอย่างเดียว) เพื่อเลี่ยงใบอนุญาตและความรับผิด
4. **รูปแบบนิติบุคคล/ชื่อผลิตภัณฑ์** ของฝั่ง marketplace (แยกจากเครื่องมือ BOQ ไหม)
5. **LINE OA** เป็นช่องทางหลักฝั่งซับ/ร้านหรือไม่ (มีผลต่อสถาปัตยกรรมการแจ้งเตือน)
6. **ราคา subscription** และสิ่งที่ฟรี/ไม่ฟรีใน BOQ เมื่อเพิ่มโมดูลจัดหา
