# แผนทดสอบอัตโนมัติ ConTrack — BOQ Estimate มาตรฐาน + โมดูลจ้างช่วง (ด้านการจัดคน)

สถานะ: ใช้งาน · 2026-10-27 · branch `test/robot-e2e`

## 1. เป้าหมาย

- **สูตรถูกทุกตัว**: ทุกเครื่องคำนวณ 36 ตัวใน 37 ขั้นตอน มี unit test ที่ครอบคลุมทั้งค่าปกติและค่าขอบ ตัวเลขต้องตรง Excel v5
  (golden + oracle เดิม) และเพิ่มกรณีที่ Excel ไม่ได้ทดสอบ: ค่าว่าง ศูนย์ ติดลบ ค่าใหญ่มาก ทศนิยมขอบการปัดเศษ แถวไม่จำกัด
- **เล่นจบได้ทั้ง 37 ขั้นตอน** บนหน้าเว็บจริง ตั้งแต่สร้างโครงการ → กรอกตามแบบ → ยืนยันทีละขั้น → BOQ → แผนงาน
  (Man-Day, S-Curve, Cash Flow) → ส่งออก และยอดเงินบนจอต้องเท่ากับที่ engine คำนวณจากข้อมูลชุดเดียวกัน
- **API และฐานข้อมูลถูกต้อง**: ทุก route ของ core (auth, workspace, ทีม, โครงการ, revision, การมอบหมายขั้นตอน) ทดสอบสิทธิ์
  ทุกบทบาท ทดสอบ input ผิด และอ่านแถวในฐานข้อมูลกลับมาตรวจหลังการเขียนทุกครั้ง
- **โมดูลเสริม**: เน้นโมดูลจ้างช่วง (subcontracting) ด้าน "การจัดคน" — แตกงานจาก BOQ เป็นแพ็กเกจ เชิญทีมช่าง
  ทีมช่างเสนอราคา เทียบราคา ตกลงจ้าง ทำสัญญา และการเปิด-ปิดโมดูลแล้วระบบกลับเป็น BOQ ธรรมดา
  ไม่ทดสอบ materials / owner-leads / ai-assist ในรอบนี้

## 3. เทคนิคออกแบบเคส (มาตรฐาน QA)

- **Equivalence partitioning**: แบ่งค่าเป็นกลุ่ม (ว่าง, ศูนย์, ปกติ, ทศนิยม, ติดลบ, ข้อความ, สูตร `=9.5+7`)
- **Boundary value**: ขอบการปัดเศษ (ROUNDUP/CEILING), ขอบ MAX(1,…), จำนวนแถว 0/1/ตามตัวอย่าง Excel/มากกว่า Excel,
  ความยาวชื่อสูงสุด, TTL ของโทเค็น
- **Decision table**: ขั้นตอนที่ต้องกรอก vs ไม่บังคับ (`docs/rebuild/REQUIRED_FIELDS.md`), สิทธิ์ตามบทบาท × การกระทำ
- **State transition**: ขั้นตอน locked → current → done / skipped → กลับมาแก้, แพ็กเกจ draft → เปิดรับราคา → ตกลงจ้าง → สัญญา
- **Error guessing**: กดซ้ำเร็ว ๆ, รีโหลดกลางทาง, ย้อนกลับ, เปิดสองแท็บ, version conflict, ลบแถวสุดท้าย, ชื่อภาษาไทยยาว/อีโมจิ
- **Data integrity**: หลังทุกการเขียนผ่าน API อ่านแถวจาก PostgreSQL ตรวจค่า, ตรวจว่าไม่มีข้อมูลรั่วข้าม workspace
