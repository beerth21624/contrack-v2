## 1. สิ่งที่เรียนรู้จาก Excel (ที่เปลี่ยนวิธีคิดของระบบ)

1. **ไม่มี "price list กลาง"** — ราคาต่อหน่วยพิมพ์ไว้ที่แต่ละแถวของ BOQ Home (คอลัมน์ I วัสดุ, K ค่าแรง) ชีตเครื่องคำนวณส่งมาแค่ "ปริมาณ" ระบบเดิมที่มี price list 500+ รหัสแล้ว map เข้า BOQ จึงเป็นโมเดลที่ผิดตั้งแต่ต้น
2. **BOQ Home คือรายการตายตัว 32 หมวด (0–31)** แต่ละแถวมี: รายการ, หน่วย, ปริมาณ (ลิงก์จากเครื่องคำนวณหรือพิมพ์เอง), %เผื่อ, ราคาวัสดุ, ราคาแรง, หมายเหตุ
   - H = E × (1+G) ปริมาณรวมเผื่อ · J = I × H ค่าวัสดุ · L = K × E ค่าแรงคิดปริมาณสุทธิ · M = J + L
   - **ข้อยกเว้น:** บางแถวคิดค่าแรงจากปริมาณรวมเผื่อ (K × H: ท่อน้ำทิ้ง, ท่อน้ำดี, ท่อร้อยสาย, สายไฟ, วงกบประตูไม้) และบางแถวคิดค่าวัสดุจากปริมาณสุทธิ (J = I × E: แถว 186, 190) → ระบบต้องกำหนด "ฐานค่าวัสดุ / ฐานค่าแรง" รายแถว
   - บางแถวมีปัดเศษ (คอนกรีตโครงสร้าง `MAX(1, CEILING(E×(1+G), 0.25))`, เหล็กโครงหลังคาปัดขึ้นเป็นท่อน)
   - แถว "วัสดุอุปกรณ์และของใช้สิ้นเปลือง" = % ของ (วัสดุ+แรง) ของแถวกลุ่มเดียวกัน (15% ไฟฟ้า, 50% ประปา)
3. **บางหมวดมีจำนวนแถวไม่ตายตัว** — เหล็กเสริมแตกเป็น 1 แถวต่อขนาดเหล็กที่ใช้จริง, ประตู-หน้าต่าง 1 แถวต่อบาน, รายการเลือกจาก dropdown (ตู้ไฟ, อุปกรณ์ไฟฟ้า, สุขภัณฑ์, เบ็ดเตล็ด) 1 แถวต่อรายการ
4. **เครื่องคำนวณลิงก์กันเอง** เช่น ฉาบ ← ก่ออิฐ, ก่ออิฐหักช่องเปิด ← ตารางประตู-หน้าต่าง, สี ← ฉาบ + ฝ้า, โครงหลังคา ← พื้นที่ลาดเอียงจากมุงหลังคา, ดินถมกลับ ← ฐานราก − ตอม่อ, สายไฟ ← วงจรท่อร้อยสาย, ตัดหัวเข็ม ← จำนวนเสาเข็ม
5. **หลายแถวใน Excel พิมพ์ซ้ำแทนการลิงก์** (เช่น ค่าตรวจสอบที่ดิน 7,500, น้ำไฟชั่วคราว 6,500/1,500, แคมป์, วางผัง) — ระบบใหม่ควรลิงก์อัตโนมัติ (รอ owner ยืนยัน, ดูข้อ D3)
6. **Man-Day เป็นสำเนา BOQ ทั้งแผ่นที่พิมพ์ราคาซ้ำ** — ระบบใหม่คำนวณจาก BOQ ตัวเดียว ไม่ทำสำเนา
7. Excel มีบั๊ก/สูตรแปลกหลายจุด (SUM ไม่ครอบทุกแถว, คำอธิบายสลับ, waste สลับ ฯลฯ) — แยกเป็นรายการตัดสินใจ (หัวข้อ 8)

## 2. หลักการออกแบบ

1. **Excel เป็นสเปก, golden test เป็นเกณฑ์ผ่าน** — ใส่ค่าตัวอย่างจาก Excel v5 แล้วผลต้องตรงค่าที่ Excel คำนวณไว้ (ทุกแถว BOQ, ทุก subtotal, grand total 1,850,317.34) ยกเว้นจุดที่ owner อนุมัติให้แก้บั๊ก
2. **ไม่มีรายการเกิน Excel** — ไม่มีเครื่องจี้, ลูกปูน, ปั๊ม, บ่ม, แอร์ ฯลฯ ถ้าลูกค้าอยากได้ทีหลังค่อยเพิ่มเป็นแถว BOQ จริง
3. **โครงสร้างข้อมูลแยกจาก UI** — logic ทั้งหมดเป็น pure function ทดสอบได้ด้วย unit test ไม่ผูกกับ React
4. **ประกาศแทนเขียนซ้ำ (declarative)** — BOQ template เป็นข้อมูล (แถว, หน่วย, ราคาตั้งต้น, ที่มาของปริมาณ) ไม่ใช่โค้ด mapper ยาว 700 บรรทัดแบบเดิม
5. **หน้าจอเลียน Excel** — ช่องกรอก (เหลือง) / ช่องคำนวณ (เขียว), ตารางเพิ่มแถวได้ตรงที่ Excel มีตาราง, ป้ายภาษาไทยตาม Excel

## 3. โครงสร้างข้อมูล (Domain model)

```ts
// โครงการ 1 งาน = ทุกอย่างที่ผู้ใช้กรอก (persist ตัวนี้ตัวเดียว)
interface Project {
  schemaVersion: number;
  meta: ProjectMeta;                       // หัว BOQ Home: โครงการ, สถานที่, เจ้าของบ้าน, Revision, วันที่, ผู้จัดทำ
  calculators: Partial<Record<CalcId, unknown>>;   // input ของแต่ละเครื่องคำนวณ (ตาม schema ของมัน)
  boqOverrides: Record<BoqLineKey, BoqLineOverride>; // ผู้ใช้แก้ในหน้า BOQ: qty (แถวกรอกเอง), %เผื่อ, ราคาวัสดุ/แรง, หมายเหตุ, ชื่อรายการ
  planning: { manday: ManDayInput; schedule: ScheduleInput; cashflow: CashFlowInput };
}

// เครื่องคำนวณ 1 ตัว = 1 ชีตใน Excel
interface CalculatorDef<I, O> {
  id: CalcId;                 // เช่น 'land-inspection', 'footing', 'brick', 'paint'
  sheetName: string;          // ชื่อชีต Excel ที่อ้างอิง
  defaults: I;                // ค่าตัวอย่างจาก Excel v5 (ใช้เป็น seed + golden test)
  deps: CalcId[];             // ต้องใช้ผลของเครื่องคำนวณไหน (cross-sheet link)
  compute(input: I, ctx: CalcContext): O;  // pure; ctx.get('brick') ได้ผลของตัวอื่น
}

// แถว BOQ ในแม่แบบ (ข้อมูลล้วน)
interface BoqLineTemplate {
  key: BoqLineKey;            // stable id เช่น '6.rebar.footing', '24.item' (แถวไม่ตายตัวใช้ generator)
  section: number;            // 0–31
  itemNo?: string;            // '1)', '2)' …
  desc: string | ((ctx) => string);
  unit: string;
  qty: { calc: CalcId; output: string } | { manual: number };  // ลิงก์หรือกรอกเอง
  waste: number;              // %เผื่อตั้งต้น (fraction)
  mat: number; lab: number;   // ราคาตั้งต้นจาก Excel v5
  materialBasis?: 'gross' | 'net';          // default 'gross' (J = I×H)
  labourBasis?: 'net' | 'gross';            // default 'net'   (L = K×E)
  rounding?: 'concrete' | 'ceilInt' | ...;  // กฎปัดเศษเฉพาะแถว
  note?: string;
}
// หมวดที่แถวไม่ตายตัว (เหล็กแยกขนาด, ประตูทีละบาน, pick-list) ใช้ generator:
type BoqLineGenerator = (ctx) => BoqLineTemplate[];
```

**การคำนวณทั้งโครงการเป็นฟังก์ชันเดียว**
```
computeProject(project) =
  1) คำนวณเครื่องคำนวณทั้งหมดตามลำดับ deps (topological)
  2) ขยาย BOQ template + generators → แถว BOQ
  3) ใส่ overrides ของผู้ใช้ → คิด H/J/L/M, ของใช้สิ้นเปลือง %, subtotal, grand total
  4) Man-Day ← labour/total ต่อหมวดจาก BOQ
  5) S-Curve ← ระยะเวลา/งบจาก Man-Day + วันเริ่มที่กรอก
  6) CashFlow ← grand total + น้ำหนักรายสัปดาห์จาก S-Curve
```
ทุกหน้าจอเรียกผลจากฟังก์ชันนี้ (memoized) ไม่มีการ "บันทึกผลคำนวณ" ลง storage แบบเดิม (`stepSaves.res`) — เก็บเฉพาะ input จึงไม่มีปัญหาข้อมูลเก่าค้าง
